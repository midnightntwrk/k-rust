# R2-G-05 executable pre-CF configuration-hook prototype

Status: pass on 19 August 2026.

Verdict: the pinned frontend can support the proposed
`OfficialConfigurationTransformHook-v0` as a two-source classpath overlay. The
hook composes with the unchanged `OfficialDefinitionAdapter v1` and preserves
official ownership of configuration parsing, checks, CF generation, later
parsing, lowering, Kore emission, and execution.

## Contract and exact patch surface

The experimental contract is one synchronous
`Function<Definition, Definition> transformConfigurations`. It runs exactly
once after all configuration bubbles have become typed `Configuration`
sentences and before `checkConfigCells` and
`GenerateSentencesFromConfigDecl.gen`. Existing entry points delegate with
`Function.identity()`. A null result becomes a compiler error at
`post-config-parse-pre-cell-check`; transformer exceptions propagate before CF
output exists.

The checked patch changes only:

- `DefinitionParsing.java` (+38/-4): adds identity-default overloads, carries
  the function into the private typed operation, applies it at the midpoint,
  rejects null, and passes the returned definition to checks and generation.
- `Kompile.java` (+39/-2): adds two-function `run` and `parseDefinition`
  overloads while retaining the old signatures and the existing post-CF
  pipeline unchanged.

The patch SHA-256 is
`bf9c788c89a201e74c9a51df23fe544333c8bf9898a8a9973dc4163d86f3e543`.
Replay copies only these exact sources into ignored task build output, applies
the patch there, and compiles the two overlay classes. The external checkout
and installed distribution are never modified. Signatures and bytecode verify
the old and new entries, overlay classpath precedence, and the order
`Function.apply -> checkConfigCells -> config-generation transform`; the
generation lambda is separately bound to
`GenerateSentencesFromConfigDecl.gen`.

## Positive outcomes

The default entry and explicit identity hook both match a fresh unpatched P3
baseline. Focused alpha-normalized definition Kore, syntax Kore, macros, and
runtime agree. Explicit identity receives and returns the same official
`Definition` reference, with 65 modules, 562 local sentences, three
configurations, 14 primary-source sentences, and the same content fingerprint.
The post-CF adapter returns the same reference in the same invocation.

The fixture-specific augmentation selects exactly one `P3-COUPLED`
configuration by module and source provenance. It clones the parsed `<state>`
cell's typed constructor/token metadata to create
`<observation> 0 </observation>`, adds it as a sibling without parsing source,
and preserves the configuration `ensures`, attributes, source/location,
cardinality, every old subtree, imports, module fields, and all non-config
sentences. Official CF removes the `Configuration` and generates
`ObservationCell`, its production, initializer, projection, and rules before
the post-CF adapter.

Two fresh augmentation outputs have equal normalized definition Kore, syntax
Kore, macros, fingerprints, and runtime. Execution is `<k> 1`, `<state> 2`,
`<observation> 0`; observation erasure equals baseline. The focused official
generation marker counts equal the ordinary-source fallback. Provenance differs
as expected: the typed clone retains `coupled.k` and the reused state-cell
location `20,7,20,25`, while the source fixture records its own file and
observation location `21,7,21,37`.

## Negative outcomes

All four negatives use fresh outputs and produce neither `definition.kore` nor
`compiled.bin`:

- null result: rejected at `post-config-parse-pre-cell-check`, before task
  validation, CF output, post-CF adapter, or backend;
- sentinel exception: rejected at the same boundary and stages;
- non-configuration Bubble change: rejected by task validation before the
  official cell check; and
- duplicate `<k>`: passes task validation as a one-configuration body change,
  then is rejected by the official transformed-input cell check before CF
  generation or backend.

## Pins, cycles, and limitations

The activation revision is `d16e1aee298b8008f9a33e26b3aaceb056c3ad80`.
K is v7.1.337 at `4a46d1231473b599c699160132fd6e76a5c46406`.
The source hashes, installed frontend-jar hash, source status
(` M pyk/uv.lock`), class hashes, environment, compact traces, projections,
and commands are bound in `results.json` and regenerated by `verify.sh`.

Three substantive full-oracle cycles were used: cycle 1 completed all compiler
and runtime probes but exposed an overlong wrapped-diagnostic grep; cycle 2
passed after narrowing that evidence check; the final acceptance replay is
cycle 3. There was no packet ambiguity requiring a split.

This is a fixture-specific inert-cell oracle and an upstream-shaped overlay,
not an accepted K API. It introduces no configuration transport or K-facing
patch, event vocabulary, rule instrumentation, trace, matcher, symbolic runner,
C1, or C2 behavior.
