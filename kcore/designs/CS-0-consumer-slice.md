## 2. The bridge statements

### 2.1 How the two term models line up (shown by reading)

| K value | k2lean (`KImp/Terms.lean`) | KCore (`Core.lean`, `Value.lean`) |
|---|---|---|
| constructor of a sort without subsorts | `Term.ck (c : Ck s) a…` at tag `s` | `.ctor f [v…]`, `sortOf` = its result sort |
| own constructor of a sort with subsorts | `Term.inj hs (l := S.Own) h (Term.ck …)` at tag `S` | `.ctor f [v…]` (no injection) |
| value of a subsort seen at `S` | `Term.inj hs l h a`, `l` the leaf tag (most specific sort); `Term l` is never an `inj` (`hasLeaves l = false`) | `.inj a b t` with `!t.isInj`, `sortOf t = some a`, `(a,b) ∈ c.subsorts` |
| Int, Bool | `b_SortInt v`, `b_SortBool v` | `.dv Srt.int (.int v)`, `.dv Srt.bool (.bool v)` |
| `Id` token | `b_SortId ⟨val⟩` | `.dv Srt.ident (.tok val)` |
| Map | `coll_SortMap (l : List (KItem × KItem))`, `WF` = sorted by k2lean's generated `Ord` (`cmp_SortKItem`, the order of `ser` token lists) | `.map Srt.map es`, `keysSorted es` by `GroundTerm.cmp` |

Both sides keep one injection from the most specific sort, so `enc` is structural except at maps, where the two orders are different functions and `enc` must re-sort.

### 2.2 `enc` (generated per library; the family's arities differ per library)

```lean
namespace KImp.Bridge
open KCore
abbrev P : Semantics := RefKimp.c

def srt : KImp.Tag → KCore.Srt          -- a tag `S.Own` maps to the sort of `S`
def sym0 : (s : Tag) → C0 s → KCore.Sym  -- and sym1, sym2, sym3: one row per constructor

mutual
def enc : {s : Tag} → KImp.Term s → GroundTerm
  | _, .b_SortInt v        => .dv Srt.int (.int v)
  | _, .b_SortBool v       => .dv Srt.bool (.bool v)
  | _, .b_SortId v         => .dv Srt.ident (.tok v.val)
  | _, .b_SortKConfigVar v => .dv Srt.kconfigVar (.tok v.val)
  | s, .c0 c               => .ctor (sym0 s c) []
  | s, .c1 c a0            => .ctor (sym1 s c) [enc a0]
  | s, .c2 c a0 a1         => .ctor (sym2 s c) [enc a0, enc a1]
  | s, .c3 c a0 a1 a2      => .ctor (sym3 s c) [enc a0, enc a1, enc a2]
  | s, .inj _ l _ a        => if srt l = srt s then enc a else .inj (srt l) (srt s) (enc a)
  | _, .coll_SortMap l     => .map Srt.map (KBridge.sortEntries (encEntries l))
  | _, .coll_SortSet l     => .set Srt.set (KBridge.sortElems (encKeys l))
  | _, .coll_SortList l    => .list Srt.list (encList l)
def encEntries : List (Term .SortKItem × Term .SortKItem) → List (GroundTerm × GroundTerm) …
end

/-- Deep well-formedness: every map and set inside the term is `MapHook.WF`, and no node is a
constructor the package does not have. -/
def Term.WF : {s : Tag} → Term s → Prop

theorem enc_sorted {s} (t : Term s) (h : t.WF) : P.sortOf (enc t) = some (srt s)
theorem enc_inj {s} {t u : Term s} (ht : t.WF) (hu : u.WF) (h : enc t = enc u) : t = u
theorem enc_ctor_inv …   -- one inversion per family constructor: `enc t = .ctor f vs → …`
def encC (c : SortGeneratedTopCell) (h : c.WF) : Config P := ⟨enc c, enc_sorted c h⟩
end KImp.Bridge
```

`srt .SortGeneratedTopCell = topCellSort` is a `decide`. The tables are untrusted: every lemma that uses them is checked against `P.sem` by the kernel.
A decoder `dec : (s : Tag) → GroundTerm → Option (Term s)` with `dec_enc` and `enc_dec` is not needed for kimp; it is needed as soon as the definition has parameter symbols (§3, item 4).

```lean
theorem step_wf {c c'} : KImp.Step c c' → c.WF → c'.WF
```

Hand-written once (`KBridge.Transfer`), over a structure holding `enc_sorted`, `enc_inj`, `step_wf`, `fwd`, `bwd`:

```lean
structure Bridge {α} (S : α → α → Prop) (WF : α → Prop) (c : Semantics) (enc : α → GroundTerm) where
  sorted : ∀ a, WF a → c.sortOf (enc a) = some topCellSort
  inj    : ∀ a b, WF a → WF b → enc a = enc b → a = b
  wf     : ∀ a b, S a b → WF a → WF b
  fwd    : ∀ a b (ha : WF a) (hb : WF b), S a b → Step c ⟨enc a, sorted a ha⟩ ⟨enc b, sorted b hb⟩
  bwd    : ∀ a (ha : WF a) (y : Config c), Step c ⟨enc a, sorted a ha⟩ y → ∃ b, WF b ∧ y.val = enc b ∧ S a b

def Bridge.Img (B : Bridge S WF c enc) (Q : α → Prop) (y : Config c) : Prop := ∃ a, WF a ∧ y.val = enc a ∧ Q a

theorem Bridge.preserved (B) {Q} (h : KPrelude.Preserved S Q) :
    ∀ x y : Config c, B.Img Q x → Step c x y → B.Img Q y
theorem Bridge.successors (B) (succ : α → List α) (hs : ∀ a b, b ∈ succ a ↔ S a b) (a) (ha : WF a)
    (y : Config c) : Step c ⟨enc a, B.sorted a ha⟩ y ↔ y.val ∈ (succ a).map enc
theorem Bridge.next_entailed (B) (hc : c.coreOK = true) (hf : FnHyp c) (ref : StepFn) (href : StepIs c ref)
    {Q} (h : KPrelude.Preserved S Q) (a) (ha : WF a) (hq : Q a) :
    ((Faithful.Γ c ∪ Faithful.Γstep c) ⊧
        (den c (enc a) ⇒ KoreAML.allNext (KoreAML.disjList ((ref (enc a)).map (den c))))) ∧
    ∀ y ∈ ref (enc a), ∃ b, WF b ∧ y = enc b ∧ Q b
```

`next_entailed` is the plan's "matching-logic form": every successor `Γ` forces from `⟦enc a⟧` is the encoding of a configuration where `Q` holds. It needs a `ref` with `StepIs` (F1).

**Hypotheses.** None named of the user. The proofs read the package's own facts: `ok`, `srReady`, `matchReady`, `coherent`, `prio_floor`, `rules_cases`, `kernel_rfl rule_i`, and for `next_entailed` `coreOK_defn`, `fnHyp_defn`, `deterministic` (through F1's `ref`).

**Generated by k2lean:** `srt`, `symk`, `enc`, `Term.WF`, `enc_sorted`, `enc_inj`, the inversions, `F.eval`, `Rules.ρ.fwd/bwd`, `step_wf`, `fwd`, `bwd`, `bridge`, the `Bridge` instance, the transferred statements.

## 3. What changes in k2lean

1. **Input: `gen` reads the package, not krust's `definition.kore` + `runtime.json`. Breaking** (CLI; rule names become index and label of `P.sem.rules`; the Tag set becomes the package's sorts, library sorts included; krust-only constructors go; the KRS sidecar path).
   Reason beyond "one reader": the two texts have different signatures (F4), and `enc` is onto the package's values only if the family is generated from the package's signature (F7). How the Rust generator reads a Lean value is a design choice: an export of `Semantics` by `kcore` as data, or k2lean's own reader on the same KORE. Both are safe, since every bridge lemma is kernel-checked against `P.sem`; the export has one reader to keep in step. k2lean's reader leaves the trusted base either way.
2. **`Terms`, `Functions`, `Rules` (`Step`, `App`), `Init` and the hook models of `KPrelude` move from specification to derived. Breaking** for `contract.md` §2, every `k2lean.freeze` and the gate's hashes: the frozen closure starts at the transferred statements and reaches `P.sem` and KCore's cone. They are tied by `enc_sorted`/`enc_inj`, `F.eval_iff`, `bridge`, and the hook lemmas. The user's `P` of a kind 2 invariant stays specification, now read through `Img`.
3. **Statements about `NS.Step` keep their text. Not breaking.** `Preserved`, `Step.deterministic`, `Adequacy`, the claims, `k2l_preserve` are untouched; each gains a transferred corollary from `KBridge.Transfer`.
4. **`class Hooks` becomes the package's parameters. Breaking.**
   - Its fields are `P.sem.params` with `impl = none`. With `dec`, an instance `I` gives `H_I : HookParams` (`H_I.app f vs` decodes `vs`, applies the field, encodes), and every `H` gives an instance `I_H` (`(H.app f (encs xs)).bind (dec resultTag)`); `dec` at the result tag is the same filter as `Semantics.paramVal`'s `filter fun v => c.sortOf v == some k.sig.result`.    - Silent points: none exist in the released tree. When `silentTable` gets rows, `hookRes` returns `c.hooks.app f vs` there (filtered by sort); k2lean's "documented choice" at such a point then has to be a `Hooks` field too (theorems for every interpretation), or the bridge is stated at the one `H` that makes the same choice. Two readings both pass; the first asserts less.
   - Uncovered function points: `none` on both sides today (`Eval.undef`; `design.md` §2 "Where no equation applies the result is `none`"). If KCore makes them parameter values, k2lean's cascades end in a `Hooks` field instead of `none`. Conditional on a KCore change I did not read.
