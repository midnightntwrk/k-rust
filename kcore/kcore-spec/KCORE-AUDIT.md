Date: 2026-11-08 (M3.1, drafted as `../m3-spec/AUDIT.md`; landed with F2 the same day, M3.2). Subject: the axioms that F2's three new fixed texts (`prelude/f2-intid.kore`, `f2-intidstring.kore`, `f2-domains.kore`) put into Γ_D.
Danger looked for: an axiom false in the intended standard model. Γ_D with a false axiom has no standard model, and `StdModelOK`, so soundness and completeness, would fail or hold vacuously.

**As landed** (KCORE-SPEC.md §9; the recommendations below taken as decided):

- INJ composition stays out of Γ_D (it is `[simplification]`), and Cons-Coh is stated over every chain of `subsorts`, which holds the closure of the declared pairs (§4).

It must be fixed (the premise `ToCount =/=String ""` on the recursive equation) before any fragment interprets the String hooks.
- `#remove`'s and `substrString`'s definedness axioms are kept, for the reasons of §6 and §2.1.

### 2.3 The empty needle: `countAllOccurrences` and `replaceAll` are false for the documented `findString`

Text (DOMAINS, also INT+ID+STRING):

    axiom{R} \exists{R}(Val:SortInt{}, \equals{SortInt{}, R}(Val:SortInt{}, LblcountAllOccurrences…(K0:SortString{}, K1:SortString{}))) [functional{}()]
    countAllOccurrences(Source, ToCount) = 1 +Int countAllOccurrences(substrString(Source, findString(Source, ToCount, 0) +Int lengthString(ToCount), lengthString(Source)), ToCount)
        requires findString(Source, ToCount, 0) >=Int 0

Counterexample: take `Source = "a"`, `ToCount = ""`. The documented `findString` returns the first position at or after the index where the needle occurs, so `findString("a", "", 0) = 0`. With `lengthString("") = 0` and `substrString("a", 0, 1) = "a"` (valid indices), the equation becomes `c = 1 +Int c` for `c = countAllOccurrences("a", "")`. No integer satisfies that, and the functional axiom says c is an integer.
`replaceAll`'s functional axiom fails with it: `replaceAll("a", "", R) = replace("a", "", R, countAllOccurrences("a", ""))` is defined only if c is.
So in every model of Γ_D in which `lengthString` and `substrString` have their documented values on valid indices, `findString("a", "", 0) ≠ 0`, against the documented 0. Γ_D stays consistent because F2 leaves `findString` loose: `findString(S, "", I) = -1` makes `countAllOccurrences(S, "") = 0` and `replaceAll(S, "", R) = S`, and every other axiom holds (§8).
Nothing in F2 depends on it today: `rhsCtx` lets rules call only interpreted hooks (DefinitionWf.lean), so no F2 step evaluates a String hook.
Recommendation: **refine** the recursive equation in Γ_D with the premise `notBool (ToCount ==String "")`, or curate it out, before any fragment gives String hooks their documented meaning. Until then, record the loose `findString` as the reason Γ_D has a model. Curating out the two functional axioms instead would leave `countAllOccurrences(S, "")` undefined, against the hook's declared `total`.

## 3. `_Set_` and idem

KCORE-SPEC.md Q29 first read `_Set_` as union (total); since 2026-11-13 it reads it as the union of two disjoint sets, undefined on overlap. Under union every SET axiom of the texts holds [V: on all 8 sets over {a,b,c}, assoc 512 of 512, unit 8 of 8, idem 8 of 8, and the `|Set` equation 64 of 64]. Under the disjoint reading `idem` fails for 7 of 8 sets (all but `.Set`), and the others hold: assoc (both sides defined exactly when the three sets are pairwise disjoint, and then equal), the units, the `|Set` equation (`S2 -Set S1` is disjoint from `S1`), and SET-KORE-SYMBOLIC's `#Ceil(@S SetItem(@E))` lemma, which under union is false at `@E ∈ @S`. The text has no `comm` axiom for `_Set_`; both readings are commutative.

The disjoint reading is the one K's sources state: domains.md's prose ("the concatenation of two sets containing elements in common is `#False`"), `|Set` defined as `S1 (S2 -Set S1)`, the `#Ceil` lemma, the manual's "distinct elements" of a set pattern (findings/SET-concat-evidence.md §1). The `idem` attribute, which kompile writes as `\equals(_Set_(K, K), K)`, is the one statement against it; with the `#Ceil` lemma it makes KEVM's text unsatisfiable. The collection axioms of `Γ` are KCore's own (`ΓColls`), so the idempotence axiom is classified `unread setIdempotence` (stated by the text, deliberately not read, Parse.lean), the library's and each cell set's alike. Verdict on the text's `idem` axiom under the reading: **F, not read**.

## 4. Subsorts and the INJ composition axiom

**Closure** [V]:
- INT+ID and INT+ID+STRING declare only `X < KItem`, so the closure has no chains.
- DOMAINS declares 19 pairs, closed under transitivity with 5 chains: IOError < IOInt, IOFile and IOString < KItem; Int < IOInt < KItem; String < IOString < KItem. Every closure pair has its `[subsort]` axiom.
- kink's IMP has 47 pairs and 15 chains. kimp has 25 declared and 29 in the closure, and leaves four pairs undeclared: Int and Bool < Expr, Int and Bool < KResult.

On kimp's four pairs the KORE has no `[subsort]` axiom, so `inj{Int,Expr}`'s definedness comes from Cons-Coh alone (KCORE-SPEC.md §3.3).

**Cons-Coh over the closure**: `inj{B,C}(inj{A,B}(x)) = inj{A,C}(x)` for every chain A < B < C. It is true in the term model, because the normal form of either side is `inj{own(x),C}(core(x))` [V: every bounded instance, no failure].

**The INJ composition axiom** `inj{S2,S3}(inj{S1,S2}(T)) = inj{S1,S3}(T)`, for all sorts, is `[simplification]`, so it is not in Γ_D. Is it true exactly on chains? Not quite [V: instances over each text's sorts, `f2-audit.txt`]:

| kind of instance | DOMAINS | kink's IMP | verdict |
|---|---:|---:|---|
| a. chain S1 ≤ S2 ≤ S3 | 58 | 142 | true: Cons-Coh, with `inj{S,S}` the identity (F2 never builds `inj{S,S}`) |
| b. S1, S2 ≤ S3, S1 ≰ S2, and S1 has an element not from below S2 | 200 | 1,032 | **false whatever the unlicensed `inj{S1,S2}` denotes** |
| b′. as b, but every element of S1 comes from below S2 | 0 | 0 (kimp: 3) | true under the partial-inclusion reading of unlicensed injections |
| c, c′. the outer or the right injection unlicensed | 3,117 | 34,763 | decided only by how unlicensed injections are read; under partial inclusion 2,604 true and 513 false (DOMAINS) |

Partial inclusion reads `inj{A,B}(x)` as the B-element with x's core if x's own sort is ≤ B, and ∅ otherwise. On licensed pairs it is F2's injection.

Why b is false, on DOMAINS' own signature: S1 = Int, S2 = IOError, S3 = IOInt, T = 5. The right side `inj{Int,IOInt}(5)` is one element (`[subsort]`). The left side is ∅ if `inj{Int,IOError}(5)` is. Otherwise IOError's no-junk axiom makes `inj{Int,IOError}(5)` a K-IO constructor e, and `inj{IOError,IOInt}(e)` differs from `inj{Int,IOInt}(5)`: in the term model they are distinct values, and in any model by the refined Cons-Dist, since Int and IOError have no common lower bound.
So the axiom is true on chains, false on every instance of kind b, and on the rest it depends on a reading no axiom fixes. Recommendation: **keep it out of Γ_D**, as now, and state Cons-Coh over the closure's chains in Γ_cons. That is the TRANSLATION.md F1 decision, now over the closure.

## 5. Cons-Dist with several supersorts

**F1's schema is inconsistent for every definition that imports DOMAINS**, even before any user subsort [V]. F1's Cons-Dist states `¬(inj{IOInt,KItem}(x) = inj{IOString,KItem}(y))` for all x, y, since IOInt and IOString are incomparable. Cons-Coh on the declared chains IOError < IOInt < KItem and IOError < IOString < KItem makes both `inj{IOInt,KItem}(inj{IOError,IOInt}(#EOF))` and `inj{IOString,KItem}(inj{IOError,IOString}(#EOF))` equal to `inj{IOError,KItem}(#EOF)`.
The library alone has 3 such pairs: IOInt, IOFile and IOString pairwise, with IOError below them. kink's IMP adds 4 (AExp/KResult, AExp/IOInt and IOInt/KResult through Int, BExp/KResult through Bool), and kimp has Expr/KResult through Int, Bool and Value. The bounded term model shows F1's schema violated 12 times on DOMAINS, 20 on kink's IMP and 4 on kimp.

**The refinement**, exactly. For a sort N and two distinct sorts A, B with A < N and B < N in `subsorts` (the closure, the cells' pairs and every sort below KItem), let `L(A,B) = {C | C ≤ A ∧ C ≤ B}`, where ≤ is the reflexive closure. Let `ι{C,A}` be `inj{C,A}` for C < A and the identity for C = A. Then

    [Cons-Dist′]  x ∈ ⟦A⟧ ∧ y ∈ ⟦B⟧ ∧ inj{A,N}(x) = inj{B,N}(y)  →  ⋁_{C ∈ L(A,B)} ∃z ∈ ⟦C⟧. x = ι{C,A}(z) ∧ y = ι{C,B}(z)

The empty disjunction is ⊥, so for A, B without a common lower bound this is F1's Cons-Dist. For comparable A < B it is implied by Cons-Inj and Cons-Coh, with the disjunct C = A, and may be omitted as F1 omits it.
Given Cons-Coh over the closure, the disjunction over L(A,B) is equivalent to the disjunction over its maximal elements: kimp's Expr/KResult needs only C = Value.
Cons-Dist between a constructor of N and an injection into N is unchanged.

**True in the term model** [I, and V on bounded instances]. A value x of sort A is a non-injection v of own sort A, or `inj{C,A}(v)` with v of own sort C < A. Then `inj{A,N}(x) = inj{own(v),N}(v)`, and own(v) ≤ A < N, so the result is an injection.
Suppose `inj{A,N}(x) = inj{B,N}(y)`. Equal terms have equal source sorts and equal cores: own(core x) = own(core y) =: C and core x = core y =: z. Then C ≤ A and C ≤ B, so C ∈ L(A,B), z ∈ ⟦C⟧, and by the normal form x = ι{C,A}(z), y = ι{C,B}(z). ∎
The bounded check (`TermModel.check`, a copy of Value.lean's normal form) found 0 violations of Cons-Coh and Cons-Dist′, over 1,218 pairs for DOMAINS (28 with equal images), 5,004 for kink's IMP (51) and 1,005 for kimp (35).
Cons-Dist′ is also what `ModelsStandard` needs: distinct normal forms denote distinct elements.
Recommendation: **refine** the Cons-Dist generator to Cons-Dist′ (KCORE-SPEC.md §3.3, Q25), now justified for every DOMAINS definition.

- definedness of the constructors and of `#stdin`, `#stdout`, `#stderr`, `#remove`, `#logToFile`, `#log`, `#trace`, `#traceK`;
- the equations `#open(S) = #open(S, "r+")` and `#stdin = 0`, `#stdout = 1`, `#stderr = 2`.

**No axiom states what `#system`, `#open/2`, `#read`, `#getc` or any other effectful hook returns**: none of them has a definedness axiom or an equation [V]. `#systemResult` occurs only in constructor axioms, which hold in the term model.

The one undecided axiom is `#remove`'s definedness, `∃v. v = #remove(P)`. domains.md says `#remove` "returns `.K` on success or an `IOError` on failure", which depends on the file system, not on P. Any fixed total function satisfies the axiom, so it holds in a model, but no interpretation of a symbol follows the documented behaviour. That is a property of the impure hook, which no axiom curation can repair.
F2 does not let rules call it, since `rhsCtx` allows only interpreted hooks. Recommendation: **keep**. If a fragment ever admits calls to impure hooks, model them outside Γ_D, for example as configuration-level effects, rather than as function symbols.

## 8. Is Γ_D consistent as curated?

The fixed-text part is, to my knowledge, and the model is explicit:
- F2's values and Hooks.lean for Bool, Int, `==K`, Map and Set (union);
- Id and String as all strings;
- the documented meanings for the String hooks, except `findString(S, "", I) := -1`;
- finite sequences for List and IEEE doubles (or any set) for Float, with any total `Float2String`;
- the constant `.K` for `#remove` and the logging hooks, and any partial functions for the other K-IO hooks;
- partial inclusion for unlicensed injections and the identity for `inj{S,S}`;
- the equations themselves for every defined function.

This rests on:
- the schematic classes: 2,618 instances in DOMAINS, all the schema's, each schema true in the term model (§1);
- the 50 new non-schematic axioms argued one by one (§2), and those of INT's text re-read (§2.4), with the STRING and SET checks on bounded universes;
- the F0 and F1 audits for the rest of INT's text.

It is an argument, not a proof: `StdModelOK` for F2 is not stated in Lean.
Two caveats. First, Γ_D has no model with the documented `findString`, so the String part pins K's meaning less than it seems (§2.3). Second, the theory soundness and completeness uses also contains Γ_cons, which is consistent only with Cons-Dist′, not F1's Cons-Dist, as soon as DOMAINS is imported (§5).

## 9. Functions' closure axioms and functional axioms (2026-11-09, KCORE-SPEC.md §2.5)

The extension adds two kinds of axiom about the user's functions, both read off the core.
- **The closure axiom of each function** (Γ_closure, `fnClosureItems`): `y ∈ f(X̄) → ⋁_i ∃ȳ_i. (premise_i ∧ y ∈ rhs_i) ∨ ∃ȳ_o. (premise_o ∧ y ∈ rhs_o)`. True in the intended model, where f is interpreted by evaluation: an element of `f(v̄)` is the value `Eval` gives, which is the right-hand side of the first clause whose premise holds (or of the catch-all where none does), and `f(v̄)` is empty where `Eval` gives ⊥. Evaluation terminates, by the certificate, so `Eval` has a result at every argument. Where clauses overlap, `wf` requires them apart by their patterns or by exclusive `requires` (`clausesExclusive_sound`), so the premise that holds belongs to the clause `Eval` uses.
- **The functional axiom of a `[total]` function** (`∃y. f(X̄) = y`, in the emitted text): true in the intended model when `Eval` gives every argument a value. `totalOK` gives that: coverage by a catch-all or by the clauses without `requires`, and right-hand sides built from total symbols, earlier total functions and self calls, which end. A `requires` that is undefined only makes its clause fail, and coverage does not count clauses with a `requires`.

Not decided in Lean, as for the rest of this audit: `StdModelOK` with these axioms.

## 10. The library by module (2026-11-10, P2.3)

The six fixed texts are replaced by the builtin library by K module (Builtins.lean, KCORE-SPEC.md §2.2). What enters Γ_D from a definition's builtin part is now:
- **the generated axioms**, written by `emit` from the signature for the library's sorts, constructors, subsorts and total symbols with the generators it uses for the user's (`libBlocks`): each is an instance of a schema of §1 (no-confusion, injectivity, no-junk, `⊤ ∨ ⊥`, the functional axioms, the subsorts, `isX` and `project:X`), discharged there once. That the library's instances are exactly kompile's is checked by the tie: a KORE whose generated part differs is not tied (39 texts tied by compiled check, and every example by the kernel, findings/P2.3-builtins-by-module.md);
- **each imported module's text**: its declarations and its hand-written axioms, and the few generated sentences that are not schematic in the signature (LIST's, SET's and MAP's assoc, unit and idem; MAP's definedness lemma of a concatenation, a simplification; K-IO's selectors; the functional axioms of `ite` and `lengthBytes`, which have sort parameters).

Every axiom of the library's text has a verdict [V: `python3 -I findings/work/p23/audit_lib.py`, which reuses §1's and §2's classification and verdicts and fails on an axiom without one; `findings/work/p23/verdicts.tsv`]. 208 axioms in 37 modules (with the kernel text):

| verdict | axioms | what |
|---|---:|---|
| S | 121 | `[simplification]`: not in Γ_D (D2), among them MAP-KORE-SYMBOLIC's 25, SET-KORE-SYMBOLIC's 22 and krust's INT-SYMBOLIC-KORE-AMENDMENTS' 5 |
| T | 46 | true in the standard model: the interpreted hooks' equations (Bool, Int, `==K`, Set and Map algebra), the kernel's projections and predicates, K-IO's descriptor equations |
| T-def | 20 | the definition of a library function no hook interprets, so a parameter: BYTES' `Int2Bytes` without a length (5), STRING-BUFFER-IN-K's buffer (3), STRING's `Bool2String` and `String2Bool`, `freshId`, INT's `bitRange` and `signExtendBitRange`, K-IO's `#open` and descriptors. Its equations hold for the interpretation they define |
| T-loose | 18 | about a parameter, true for K's documented meaning (String, List, K-IO, Bytes hooks; §2) |
| T-loose* | 3 | STRING's `countAllOccurrences` and `replaceAll` at the empty needle (§2.3), unchanged |

**What changed in the argument.** A builtin function or hooked symbol that Hooks.lean does not interpret is now a **parameter** of the definition (KCORE-SPEC.md §2.2), not an uninterpreted symbol outside the core. Every theorem about such a definition holds for every interpretation H (`withHooks`), so in particular for an H satisfying the module's axioms about the symbol (T-def, T-loose). Γ_D's graph of the symbol is H's (`ΓDom`), so soundness and completeness are stated for an H that is a model of these axioms; for T-loose* no documented H is one, as before.

**Bytes** is a byte sort (`Lib.byteSorts`): its values are the literals whose characters are below 256, distinct literals distinct (`dvOK`, Γ_D's `ΓDom`), K's documented byte strings, one character per byte.
