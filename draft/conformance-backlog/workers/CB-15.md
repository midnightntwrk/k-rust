# CB-15 Committed-trace console IO

State: closed 2026-09-20 after implementations `8fb9a55`, `d5eb262`, `d983b8d`, `12737c0`, `eb9e39b`, and `7a2ebe6`, plus the CB-15-6 closure commit and sequence 31.

## Measured failure

Shared sequence 18 originally recorded 98 plain tutorial executions halting on `IO.write` after the definitions had computed their output.
CB-09 C9, merged at `8f34df5`, established the independent batch boundary under `--io off`.

CB-15-6 sequence 31 records all 118 driven steps of the four cases as matches in 201.5 seconds at `--jobs 2`, with 1,459 MiB peak RSS.
The cases take 130.1, 70.3, 62.4, and 71.3 seconds and retain 103 definition-computed C9 console matches.
SIMPLE untyped `matrix.simple` first records the attributed `STDIN-STREAM.stdinParseInt`/`String2Int(\"\")` C9 precondition failure in 0.5 seconds, then matches its 607-byte checked-in output through committed pre-buffered `--io on` in 13.7 seconds.
The results SHA-256 is `37e1aa7c5b4df2959e029b75cc804417aa7b34b1feebd9aeb625efe75ff7b452`.

## Cause

The missing feature is an execution-owned IO state and commit boundary, not the byte computation itself.
`IO.write` and `IO.putc` can produce pending output, but only a committed concrete trace may deliver it to the host.
`IO.getc` and `IO.read` additionally need a branch-local input cursor because their returned term controls subsequent rewriting.

C9 is the first batch implementation of this boundary: it obtains one final execution, rejects residual or alternative leaves, and observes its buffered output once.
It is not live console IO because it changes `$IO` to `off` and never evaluates the hooks.

## Decision

Console IO is a product feature.
The implementation must preserve the distinction between semantic exploration and committed execution:

- pure simplification must not touch host descriptors;
- every execution branch owns its input cursor and output transcript;
- ordinary deterministic `krun` may deliver output from committed transitions exactly once;
- captured batch mode may deliver the selected terminal transcript once;
- search rejects `--io on`, and RPC keeps IO unsupported, until a separate protocol owns branch-local transcripts;
- C9 remains the differential comparison for the tutorial corpus and an independent regression for the definition-computed bytes.

The first implementation tranche is an explicit captured batch console mode with pre-buffered stdin because its observable contract is already demonstrated by C9.
Live interactive delivery follows only after the existing effect paths have a verified commit boundary.

## Acceptance

- Direct `krust krun --io on --output none` batch execution with input and output completes and emits committed bytes exactly once.
- The three-path regression obtains `ff 80 00 41` independently from structural C9 extraction, `--output captured`, and the committed live transcript; all three are byte-identical.
- The existing rollback regression emits no rejected-candidate bytes.
- Search rejects `--io on`, and RPC retains its explicit unsupported policy.
- Pure simplification receives no console state.
- The capability inventory moves only `IO.write`, `IO.putc`, `IO.getc`, and `IO.read` for descriptors 0/1/2.
- Sequence 31 records all four tutorial cases as matches, removes the conditional `matrix.simple` exclusion, and the composed closure audit reports three excluded below-floor cases, zero non-excluded below-floor cases, and zero pending or unowned cases.

## Question disposition

1. Decided by `tickets.toml` D-11: captured batch output begins as an explicit mode. Changing the default would alter the public CLI independently of the semantic feature and requires separate usage and compatibility evidence.
2. Decided by D-11: the first tranche uses pre-buffered stdin. Live interactive input follows only after branch-local effect ownership and exactly-once delivery are proved.
3. Decided for this programme by D-11: search rejects `--io on` and RPC keeps IO unsupported. A future structured transcript representation is a separate protocol feature, not an underspecified branch of CB-15.

CB-15 is closed.
C9 remains the primary independent oracle for translatable tutorial streams, and the matrix fallback retains its attributed C9 failure before comparing a separately executed committed transcript.
