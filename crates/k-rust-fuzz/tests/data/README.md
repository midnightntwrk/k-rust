# Fixture definitions of the fuzz crate's tests

Each directory holds one K definition (or, for `coin/` and `chosen/`, a baseline and its mutants) and the programs the tests run on it.
`tests/support/mod.rs` compiles each definition in-process in the portable build (`outer::load_for_compilation` with the embedded prelude and `CompilationBackend::Rust`, then `kompile::compile_loaded_definition`), once per test binary, refuses one that compiles with any diagnostic, and exposes the compiled definitions and the text of every program.
`tests/fixtures.rs` runs the programs of each fixture through `Backend::execute` and checks the halt and the record this README promises (a "natural end" there is a clean one: a `stuck` leaf with an empty `<k>`, no constraint and no diagnostic, in a run with no stack stop, undecided solver answer, allowance refusal or unsupported hook); a fixture that stops doing what is written here fails there first.

Programs are ordinary, runnable programs: holes are declared beside them by span (`ARCHITECTURE.md` §2), so each program's anchor values are the literals written in it.
Every definition except IMP stores its observable result in an `<out>` cell (or `<status>`/`<account>` for the ledger) and empties `<k>`, so a run that finishes matches the default normal-termination pattern `<k> .K </k>` (§5.2).
Every rule a target may name carries a label, except IMP's arithmetic and comparison rules (IMP is copied unchanged; §4.2 also resolves rules by unique id or source position).

The tickets are those of `impl.toml`; the classes are those of `ARCHITECTURE.md` §5.3.

## Not covered here

- A baseline/mutant pair with equal execution digests and different rewrite orders (the source-route caveat of §4.3, T-16): the compiled KORE keeps the source order of sentences, so reordering rules changes the digest too (`coin-swapped.k`), and no fixture separates the two conditions. A test can build one from `definition_on(BackendRoute::SourceExecution { .. })` with a permuted order.
- A leaf holding the hooked `M[K]` for a missing key: k-rust evaluates that lookup to `\bottom`, so the step is undefined (`look(2)` in TAINT). TAINT's `get(2)` gives the same unevaluated partial application through a user function.
- The stall benchmark's maze (`tests/data/maze*`) belongs to FZ-13.
- A program whose run times out is not a fixture: a timeout depends on the clock, and the determinism contract keeps tests off it (§5.4).
