# Fixture definitions of the fuzz crate's tests

Each directory holds one K definition (or, for `coin/`, a baseline and its mutants) and the programs the tests run on it.
`tests/support/mod.rs` compiles each definition in-process in the portable build (`outer::load_for_compilation` with the embedded prelude and `CompilationBackend::Rust`, then `kompile::compile_loaded_definition`), once per test binary, and exposes the compiled definitions and the text of every program.
`tests/fixtures.rs` runs one program of each fixture through `Backend::execute` and checks the halt and the record this README promises; a fixture that stops doing what is written here fails there first.

Programs are ordinary, runnable programs: holes are declared beside them by span (`ARCHITECTURE.md` §2), so each program's anchor values are the literals written in it.
Every definition except IMP stores its observable result in an `<out>` cell (or `<status>`/`<account>` for the ledger) and empties `<k>`, so a run that finishes matches the default normal-termination pattern `<k> .K </k>` (§5.2).
Every rule a target may name carries a label.

The tickets are those of `impl.toml`; the classes are those of `ARCHITECTURE.md` §5.3.

| Fixture | Files | Main module (syntax module) | What it is for | Tickets, class or target |
|---|---|---|---|---|
| IMP | `imp/imp.k` | `IMP` (`IMP-SYNTAX`) | The reference language, copied unchanged from the fz26 experiment (`exp/imp.k`). Its Int literals are signed (`-3` is one token), so negative hole values round-trip. | FZ-02, FZ-04, FZ-06 |
| | `imp/commute.imp` | | `a = x + y; b = y + x;` with holes at `x = 3;` and `y = 5;`. Every natural end has equal `a` and `b`. | FZ-06 M1 acceptance: commutativity of `+Int` has no confirmed counterexample (`miss` on every case) |
| | `imp/le.imp` | | `if (x <= y) { r = 1; } else { r = 0; }` with holes at `x = 3;` and `y = 5;`. The anchor ends with `r \|-> 1`; any `x > y` ends with `r \|-> 0`. | FZ-06 M1 acceptance: `x <= y` has a confirmed counterexample (`hit`, reported as a property failure) |
| | `imp/div.imp` | | `q = x / y;` with the hole at `y = 2;`. The anchor ends naturally; `y = 0` leaves `10 / 0` on `<k>`, to which no rule applies. | FZ-04 `stuck` (a clean leaf that is an abnormal stop, mid-program) |
| | `imp/loop.imp` | | A countdown loop from `n = 10;` (the hole), ending with `s \|-> 55`. Its depth grows with `n`; `max_depth` or `max_work` 20 stops the anchor. | FZ-04 `depth-bound` and `work-bound` under a small `max_depth` or `max_work`; a natural end with three `<state>` entries is `ceil_free` (FZ-04 test) |
| UNSIGNED | `unsigned/unsigned.k`, `unsigned/sum.pgm` | `UNSIGNED` (`UNSIGNED-SYNTAX`) | A language without negative literals: its grammar imports only `UNSIGNED-INT-SYNTAX`, so `print 7 + -5 ;` parses as `plus(7, neg(5))`, not with the domain value `-5` at the hole. The anchor `print 7 + 5 ;` ends with `<out> ListItem(12) </out>`. | FZ-02 round-trip check: a negative value at the hole `5` is `rejected` |
| CHOSEN | `chosen/chosen.k`, `chosen/keys.pgm`, `chosen/set.pgm` | `CHOSEN` (`CHOSEN-SYNTAX`) | Right-hand sides that read an implementation-chosen value: `keys_list` of a two-key map (`MAP.keys_list`, class `order`) and `Set2List` of a two-element set (`SET.set2list`, class `order`). With equal arguments (`listKeys(1, 1)`) there is one key and no mark. The leaf ends naturally and carries the mark. | FZ-04: a leaf with an `implementation-chosen-value` mark is not clean, so never a hit; FZ-06 "chosen-value fixture is never a hit"; FZ-08 condition 3 |
| RULES | `rules/rules.k`, `rules/div.pgm`, `rules/check.pgm`, `rules/twice.pgm` | `RULES` (`RULES-SYNTAX`) | `div(A, B)`: rule `div`'s right-hand side `A /Int B` is undefined for `B = 0`, an undefined step; the anchor `div(10, 2)` ends with 5. `check(A)`: rule `check-hit`'s guard `A ==Int 42` fails on the anchor `check(7)`, which ends through the `owise` rule `check-miss`. `twice(21)` uses the function equation `double`. The catalog also holds `twin-a`/`twin-b` (one identity, `shared_identity`) and `dormant` (`non-executable`). | FZ-04 `undefined` (`trivial` halt); FZ-05 `fired` versus `covered` on `div` with `B = 0` (covered, not fired), `condition-reached` on `check-hit` (in `matched`, not in `applied`), refusals of `twin-a`, `dormant` and the equation `double` |
| COIN | `coin/coin.k`, `coin/flip.pgm`, `coin/count.pgm` | `COIN` (`COIN-SYNTAX`) | Baseline: `flip(N)` ends with `N` (rule `heads`) or `N + 1` (rule `tails`), two paths whose single ends differ. `count(N)` takes `N + 1` steps, so a depth bound of at most `N` leaves the baseline incomplete. | FZ-08 baseline; `baseline-incomplete` with `count` under a small bound |
| | `coin/coin-layout.k` | | Mutant: layout and comments only. Equal execution digest and equal rewrite order. | FZ-08 `equivalent` |
| | `coin/coin-swapped.k` | | Mutant: `tails` written before `heads`. Equal execution digest, a different rewrite order, so on the source-execution route strategy `any` follows the other path; the set of ends is the baseline's. | FZ-08: single paths differ, sets agree, no hit; on the source route, equal digests alone are not `equivalent` (T-16) |
| | `coin/coin-prio.k` | | Mutant: `tails` has `priority(40)`, so `flip(N)` has the single end `N + 1`, inside the baseline's set. | FZ-08: a mutant that removes an end and adds none, no hit in either mode |
| | `coin/coin-kill.k` | | Mutant: the baseline for `N <= 10`, and the single end `N + 2` (rule `skew`) for `N > 10`. | FZ-08: a mutant that adds an end, a hit for any `N > 10` from the anchor `flip(3)` |
| LEDGER | `ledger/ledger.k`, `ledger/settle.pgm`, `ledger/settle.tx` | `LEDGER` (`LEDGER-SYNTAX`) | User record sorts declared in the semantic module, outside the program sort's closure: `Tx ::= transfer(Int, Int) \| noop` and `Account ::= account(Int, Int)`. The transaction is the configuration variable `$TX`, bound to `settle.tx` (`transfer(30, 1)`). The anchor ends with `<status> applied </status>` and balance 69; an overdraft or a negative field ends `refused`. | FZ-03 and FZ-G6 data-sort values; FZ-02 configuration-variable holes and the hole-sort rule (`Tx` accepted, `Pgm` refused) |
| LOADCLAIM | `loadclaim/loadclaim.k`, `loadclaim/go.pgm` | `LOADCLAIM` (`LOADCLAIM-SYNTAX`) | The load's critical-pair check of the overlapping `anywhere` equations of `g` simplifies `td(0)`, which contradicts `td`'s `total` attribute: every run lists that record with `observedIn: load`, and no leaf carries it. `go(N)` ends with 1 for `N > 100` (rule `go-big`) and 0 otherwise (`go-small`). | FZ-04: load records do not taint leaves, so `go-big` is still reachable (a hit); they are reported once per campaign (T-5) |

## Not covered here

- The stall benchmark's maze (`tests/data/maze*`) belongs to FZ-13.
- A program whose run times out is not a fixture: a timeout depends on the clock, and the determinism contract keeps tests off it (§5.4).
