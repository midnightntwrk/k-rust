# Measure the tests your AI writes

KRS lets you write a specification of your program in Rust, run it, and use it to grade and grow the test suite an AI writes for you.
k-rust, a Rust implementation of the K Framework, runs it.

Each scene below starts in a readable state; press Play to animate it, or step through it.
After the opening problem scenes, every scene follows one small example, a `plus` function on natural numbers, and every result shown as output is one that `krs` printed for it.

### What can KRS prove compared with Lean?

<KRSProofs />

<details>
<summary>The theory is broader than the current tools</summary>

Lean builds proofs using dependent types; matching logic reasons about patterns that describe sets of values or states.
[Matching Logic Explained](https://fsl.cs.illinois.edu/publications/chen-lucanu-rosu-2020-trb.pdf) shows how matching logic can also describe dependent types and support induction.
The [Chen–Roșu paper on completeness](https://arxiv.org/pdf/2608.13306v1) studies what can be derived in particular versions of matching logic; it does not establish parity between KRS and Lean’s tools.
The comparison above concerns the proof workflows available today.

</details>

### A test corpus

A test is a program, and its expected result is whatever the specification computes for it.
Nobody guesses expected values, and nobody copies them from the implementation under test.

<Corpus />

### Coverage of the specification

Because the specification runs, you can see which of its rules each test makes fire.
That is coverage of the specification itself, not of one implementation's code.

## Mutation testing, done right

### Why people avoid mutation testing

<MutationReputation />

### Mutate the specification

Mutating the specification instead of the code changes the experience.
The specification is small, so there are few places to edit, and an AI proposes only edits that would be real misunderstandings of its meaning.
The mutation tool is in development; these scenes apply the same edits by hand, and every result is one that `krs` recorded.

<MutateTheSpec />

### Let the AI climb

Climbing is growing the corpus.
Each surviving edit becomes a new test, and the tool remembers which test catches which edit, so it never has to search for it again.

<Climb />

## Standing on K

Your KRS crate is a definition in the K Framework, a mature system for language semantics with large published definitions, such as the EVM, WebAssembly and Rust's MIR.
Each KRS item becomes a K sentence you can read, and k-rust is a reimplementation of K in Rust.

<StandingOnK />
