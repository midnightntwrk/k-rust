## Total and partial functions

`#[k::function]` declares a function symbol with a result sort and concrete syntax.
A total function promises a defined result over its intended domain.
A partial function may be undefined, which denotes semantic bottom—not `Option::None` and not a host panic.
This is not Rust `Option`; undefinedness belongs to the symbolic theory.

Function structs describe symbolic applications.
Their Rust fields are operands, not values consumed by executing Rust function bodies.

### An undefined partial application

The fixture's partial function has exactly one equation, guarded by `0 <=Int value`.
The positive claim `partial-equation` checks the defined case `#m3dPositive(7) => 7` through the pinned Haskell proof route.
Now consider the other side of that same guard:

```text
#m3dPositive(-1)
```

The head is well sorted, so this is not an authoring error.
Its only equation is inapplicable, and because `M3dPositive` was declared `partial`, the application has no denotation: semantic bottom.
There is no `None` constructor to inspect and no Rust call that returns a value.
Bottom is also not an authored `trap` term or a complete normal form; if a transition needs this result, it cannot obtain one.

The focused tour evidence gate checks the partial declaration, its sole guarded equation, the negative ground input, and the pinned proved positive case together.
This example is a static-semantics consequence, not a claimed `krun` trace: bottom is the absence of a result in the theory.

## Equations and priority

Equations define function results by matching symbolic terms.
They may carry object-Boolean `requires` conditions and numeric `#[k::priority(N)]`.
This numeric priority is an equation mechanism; it does not order transition rules.

The explicit-priority example distinguishes the zero case from a wildcard fallback.
Equation source order is not the priority value.

## Aliases and named contexts

A static alias is a reversible static clause associated with alias syntax.
It is distinct from an equation subtype and from a transition.

`#[k::context_alias]` names a reusable evaluation context with one distinguished `here` site.
The `M3dTwice` constructor selects that named context through `seqstrict(using = m3d_eval)`.
The context describes where evaluation occurs inside a framed configuration; calling the Rust-shaped function is not the model.
