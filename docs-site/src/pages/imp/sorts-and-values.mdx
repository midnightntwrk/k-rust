## Open sorts

Each entry in `k::sorts!` declares an open sort.
Other declarations may add constructors or existing types to that sort later, including from another Rust module or composed package.

`Value: Expr + KResult` declares two membership edges.
Every `Value` is therefore both an `Expr` and a framework result.
`KResult` is KRS's stopping category for evaluated terms; it is imported from the facade rather than redeclared by the language.

This resembles Rust supertraits syntactically, but the result is a symbolic subsort graph.
It does not give `Value` host methods or cause Rust values to be evaluated.

## Existing builtin members

An `impl` line adds an existing type to an open sort:

- `Id` is admitted directly to `Expr`;
- `Int` and `Bool` are admitted to `Value`;
- membership is transitive, so integers and Booleans are expressions and results as well.

These builtin names are zero-sized authoring markers for K sorts.
Operations such as integer addition later construct symbolic applications; they do not call host arithmetic functions.

## Grouping without an AST node

`#[k::bracket("(", ")")]` declares expression grouping syntax.
Parsing `(e)` produces the same term as `e`; parentheses affect parsing but do not introduce an `Expr` constructor.

Declaration order is presentation, not precedence or semantic priority.
The Rust names supply inferred identities here; no public symbol spelling is pinned.
Unknown parent sorts, duplicate declarations, or an invalid membership graph fail during expansion or semantic checking at the authored declaration.
