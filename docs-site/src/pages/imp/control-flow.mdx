## Splice work into the computation

`Sequence(s1, s2) => k::k![s1, s2]` replaces one statement with two ordered computation items.
Similarly, a nonempty block exposes its body followed by an explicit empty block.

`k::k![…]` is checked K-sequence notation.
It describes symbolic sequencing; it is not a Rust vector or iterator.

## Select evaluated branches

The `IfThenElse` rules match object-language Boolean results and select one branch.
The no-else constructor normalizes to an explicit empty alternative.

The condition field was marked strict in the grammar, so derived contexts evaluate it before these rules can match `true` or `false`.
The loop constructor is deliberately not strict: its rule unfolds one test into an `IfThen` containing the body and next loop iteration.

## Erase completed syntax

Returning `()` from `done` denotes the empty K sequence, removing `EmptyBlock()` from the computation head.
This is symbolic erase syntax, not the host unit value returned from an executing Rust function.

The clauses are unordered even though their table reads like an operational checklist.
Their names identify the authored rule sentences; moving a clause does not change constructor or cell identity.
Unexpected symbolic states become normal forms or stuck states according to applicability; they do not fall through to a hidden Rust interpreter.
