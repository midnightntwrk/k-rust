## Read it from the outside in

`M2Obj` is an open object-language sort.
Because `M2Obj` is a subsort of `KResult`, every `M2Obj` term counts as a result; later strict constructs may use `KResult` as their stopping category.

`Object` is a closed constructor family on that open sort.
Its two nullary variants produce the concrete terminals `foo` and `bar`.
Writing `Object::Foo()` in the initializer constructs a symbolic application; it does not call an interpreter for `foo`.

`Machine` gives the language one computation cell named `k`.
The initializer places `foo` in that cell as a single-item K sequence.
Configuration initialization is declarative: collecting the definition does not execute `Machine::init` as ordinary Rust runtime setup.

Finally, `foo_to_bar` relates the two object terms: conceptually, the computation changes from `<k> foo … </k>` to `<k> bar … </k>`.

The `for M2Obj` header anchors this term rule at the head of the computation cell and leaves any sequence tail framed.
When `foo` is at the head, the rule can replace it with `bar`.
When it is not, this rule is simply inapplicable.

## Rust analogy—and its limit

The constructor variants and rule patterns borrow Rust's naming and destructuring vocabulary.
Rust therefore checks paths and much of the term shape early.

The rule is not a Rust function call or an ordered `match` arm, however.
KRS collects it as an unordered transition sentence.
Adding another rule above or below it does not assign either rule a priority.
In particular, KRS declarations do not execute Rust, and `foo_to_bar` does not call an imperative rewrite function.

The Rust item names provide the definition's identities here; no public symbol name is pinned with `#[k::symbol]` in this example.
Misspelled paths and impossible Rust shapes fail during Rust compilation, while malformed KRS islands and inconsistent semantic declarations produce authored-source KRS diagnostics.

## Check the specimen

With the KRS CLI available, run this from the KRS repository root:

```sh
krs check \
  --manifest-path tests/tour-minimal/Cargo.toml \
  --package krs-tour-minimal \
  --definition main
```

The tour's fixture gate also checks formatting, deterministic lowering and emission, and the same bounded structural projection as the M2 `foo → bar` oracle:

```sh
python3 tests/tour-minimal/verify.py
```

The checked artifacts describe the same theory at each layer: the initial computation contains `foo`, the sole transition rewrites it to `bar`, and no rule rewrites `bar`.
Actual execution belongs to the stronger pinned M2 consumer gate; that gate is capability-gated rather than silently treated as passing when its K tools are unavailable.
