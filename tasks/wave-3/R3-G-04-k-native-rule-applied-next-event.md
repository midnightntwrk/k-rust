# R3-G-04: K-native exact `RuleApplied` next-event pair

## Why this is the next leaf

R3-G-03 proved that pinned ordinary K matching can consume one accepted
`RuleApplied(RuleOrigin)` head and return typed provenance bindings or exact
`#Bottom`. The accepted instrumentation appends on every firing, so the same
definition can produce two events by running the selected rule twice. No
observer, configuration, host-adapter, or external-K change is required. The
positive program is `hold(bump) + bump`: `hold-value` rewrites between the two
observed firings but emits no event. Thus adjacency is explicitly on the
observed-event clock rather than on every semantic transition.

This packet is the degenerate first `next-event` boundary: match exactly two
consecutive observed events at indices zero and one and require exact trace
exhaustion. Both occurrences come from the same instrumented rule. This packet
does not establish distinct-event order, arbitrary subsequence scanning,
`eventually-after`, intervening-event semantics, or a reusable temporal
contract.

## Objective

Add a task-owned two-bump program and run one K-authored configuration pattern
against the two fresh accepted definitions regenerated by R3-G-03:

```k
<trace>
  ListItem(ruleApplied(ruleOrigin(
    ID:String, LABEL:String, MODULE:String, SOURCE:String, LOCATION:String)))
  ListItem(ruleApplied(ruleOrigin(
    ID, LABEL, MODULE, SOURCE, LOCATION)))
  .List
</trace>
```

The repeated variable names make K enforce equality of all five origin fields
across the adjacent events. Literal `.List` makes K, not the host, enforce
exact exhaustion. The positive result must project to ordered event indices
`[0,1]`, two `RuleApplied` constructors, and two equal portable origins.

Run the same pattern on the accepted one-event program; K must return exact
`#Bottom`. Run it on a task-owned three-bump program; literal `.List` must make
K return exact `#Bottom` rather than accept a residual event. Run a second
two-event K pattern whose second label is a known unequal literal; the positive
program must also return exact `#Bottom`. These are respectively the too-short,
non-exhausted, and second-position payload negatives.
